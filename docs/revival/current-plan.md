## Sequencing rule

macOS is the leading implementation lane. D3Import, the shared canonical/Core and Metal paths, RevivalMac, and RevivalEditor establish each Phase 1–7 source-led product slice. RevivalMobile may compile and compose proven work early through its concrete UIKit target, but required physical integration of storage, input, audio-session, lifecycle, presentation, and accumulated player behavior begins in Phase 8. This is implementation order, not reduced scope: RevivalMobile and touch remain required for version 1.0 and use the same canonical world, renderer, scheduler, package, save, replay, and applicable multiplayer paths.

Roadmap phases are dependency groupings, not global barriers for every developer. Use these evidence boundaries:

1. **Mac/shared checkpoint:** the current source contract works through D3Import or the canonical boundary, shared Core/Metal where applicable, RevivalMac, and RevivalEditor where the slice has a creator path.
2. **Early mobile compatibility evidence:** target builds, unsigned generic-device builds, focused automation, and simulator checks may prove only the mobile wiring they execute. They do not create a separate Phase 1–7 closure checkpoint.
3. **Late mobile integration gate:** Phase 8 proves the accumulated package, lifecycle, presentation, touch, physical-controller, audio, storage, campaign, save, replay, memory, and thermal paths on available physical devices; Phases 9 and 10 add their applicable mobile multiplayer and release matrices.

Through Phase 7, unavailable devices, signing, development-team setup, or open mobile evidence cannot block a slice, phase, or next Mac/shared dependency island. Early evidence must not be overstated as physical mobile behavior. The Phase 8 gate and applicable Phase 9–10 matrices must close before version 1.0. A Mac/shared lane may not introduce a temporary Mac-only Core, renderer, package schema, scheduler, input model, or resource-lifetime path while direct mobile integration is deferred.

## Work-packet entry gate

Every new phase, milestone checkpoint, dependency island, subsystem, or material code group begins with the bounded [fog-of-war preflight](source-translation.md#fog-of-war-preflight). Confirmed gaps update their canonical document, ledger row, packet, or verification need. A single answerable edge stays in ordinary tracing. Only several linked unknowns that prevent a concrete contract invoke `revival-wayfinding`. The preflight has a named stopping condition and may not become an indefinite phase before implementation.
